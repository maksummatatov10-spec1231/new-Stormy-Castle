## 1. Краткий вывод

Stormy Castle — браузерная Flash-стратегия формата tug-of-war / lane battle. Игрок развивает замок, строит производственные и исследовательские здания, выпускает войска на одну или несколько дорог, захватывает/удерживает выгодные точки, использует турели и пять магических действий, а цель обычного режима — уничтожить ворота противника. В игре есть четыре режима, 15 карт, прокачка между уровнями и отдельный Boss-режим.

Файл `0.swf` — не простой ролик, а полноценный AS3/AVM2-проект с данными и исполняемым игровым движком внутри одного SWF:

- CWS-сжатый SWF версии 70, сцена `800×600`, `30 fps`, 2 кадра;
- метаданные Flex 4, дата сборки `Apr 24, 2013`, язык AS3;
- 4211 SWF-тегов, 656 экспортированных символов;
- preloader и основной ABC-блок;
- основной ABC: 5916 строковых констант, 4316 multiname, 3783 метода, 823 instance/script-записи и 3742 тела методов;
- классы `TD::MapType`, `TD::EnemyType`, `TD::StructureType`, `TD::ProjectileType`, `TD::AIBasic`, `TD::AI_waves`, `TD::ChangedObj`, `TD::MagicEffects`, `TD::Map`, `TD::VisualWorld`, `TD::TowerDefenseRules`, `scr::InGamePanel` и другие;
- 77 встроенных MP3-сэмплов, включая две музыкальные дорожки общей длиной около 102 секунд;
- все основные карты, структуры, юниты, эффекты, tutorial-строки и значительная часть SDK-обвязки находятся внутри SWF.

## 3. Что это за игра

### 3.1. Игровая модель

[WEB][SWF] Игрок и противник имеют замки с воротами. Между ними идут одна, две или три дороги. На точках строительства возводятся здания, здания производят войска или дают исследования, а войска движутся по назначенной дороге к вражескому замку. Здания можно распределять по воротам; код прямо хранит назначение строения и поддерживает массовое выделение и назначение.

[SWF] Дороги не полностью взаимозаменяемы: tutorial сообщает, что юниты на разных дорогах не могут атаковать друг друга. Мосты являются специальным исключением: дальнобойные войска на разных дорогах могут взаимодействовать возле моста. В коде для этого есть отдельные bridge tiles, bridge MovieClip и проверки `onBrige`.

[SWF] Победа обычного режима описана tutorial-строкой: `You must destroy the gates to win.` В Boss-режиме строка меняется на: `Kill the Boss Unit or destroy the enemy gates to win!` Поэтому Shelter/Flag, teleport point и другие особые точки являются тактическими объектами, а не заменой основному условию победы.

### 3.2. Режимы

[SWF] `GameData.gemeRegPrefics` содержит четыре режима:

| Внутренний индекс | Префикс | Смысл |
|---:|---|---|
| 0 | пустая строка / `Normal` | обычная игра с базовым AI |
| 1 | `Hard` | усиленный AI и дополнительные hard-параметры |
| 2 | `Boss` | Boss Den, таймер и Boss-unit |
| 3 | `Flow` | волновой режим `AI_waves` |

[WEB] Внешние карточки описывают обычный бой за ворота, производство войск, турели, support/research buildings и spells. Softpedia отдельно упоминает Boss mode. Названия и логика четырёх режимов дополнительно подтверждены SWF.

### 3.3. Прохождение и прогрессия

[SWF] Внутри есть 15 карт (`MAP_0`…`MAP_14`), расположенных в `ORDER_MAPS`. Каждая карта хранит четыре score/win-слота — по одному для Normal, Hard, Boss и Flow. После победы:

- обновляется score режима, если новый результат лучше старого;
- обновляется `resultStar`;
- при необходимости открывается следующая карта;
- отключается help для завершённой карты;
- при включённом Oopla записываются keys вида `score_Normal_Map_0`, `win_Boss_Map_4`, `map_star_4`, `locked_map_5`.

[SWF] Локальное сохранение использует `ByteArrayToSharedObject` с именем игры `StormyCastle0.9`. В сериализованный объект входят `objUp`, `MapType`, настройки help, sound и music. При Oopla-ветке часть состояния дополнительно записывается в `OoplaAPI.gameState`.

[WEB][SWF] Внешняя формулировка про merchant/shop соответствует внутренним объектам `scrMarket`, `ShopVisualState`, `objUp` и дереву metagame upgrades. Это не отдельная современная игра, а экран развития, встроенный в SWF.

### 3.4. Управление

[WEB] Карточка Kongregate помечает управление как mouse-only. В самом SWF мышь действительно является главным способом управления, но есть подтверждённые клавиатурные действия:

| Клавиша | Реальное действие в `scr::InGamePanel::onKeyDown` |
|---|---|
| `1` | выбрать Meteor, если spell готов |
| `2` | выбрать Teleport, если spell готов |
| `3` | применить Holy |
| `4` | применить Armageddon |
| `5` | применить Rain of Coins / Money |
| `Escape` | отменить выбор spell/режим ручного выбора |
| `"` / key code 34 | перейти к замку |
| `!` / key code 33 | установить верхнее положение прокрутки |
| стрелки вверх/вниз | вертикальная прокрутка карты |
| колесо мыши | прокрутка карты |
| drag | панорамирование, выделение области или выбор объектов в зависимости от режима |

Имена cursor-констант вводят в заблуждение: `ST_Magic3_fireball` используется для Meteor, а `ST_Magic5_Teleport` — для Teleport. В проверенной обработке нет подтверждения клавишных cheats `A/T/H/B/M/C` или режима бесконечных заклинаний.

### 3.5. Визуальный стиль и звук

[SWF] Сцена 800×600 построена из растрового cache-рендеринга, векторных/анимированных MovieClip-ресурсов и тайловой карты с шагом 20 пикселей. В экспортированных символах присутствуют:

- красные и синие варианты войск;
- состояния `Go`, `Attack`, `Die` для направлений `Up`, `Down`, `Left`, `Right` и диагональных/8-направленных вариантов;
- замки, ворота, здания, турели, мосты, шахты, minimap и интерфейс;
- ауры яда, щита, Holy, slow, Boss, lightning и heal;
- projectiles для стрел, мечей, магии, ballista, catapult и cannon;
- эффекты Meteor, Armageddon, teleport и rain of coins.

В SWF найдено 77 MP3 в формате 11 kHz, суммарно примерно 178.83 секунды. В том числе `s_introMusic` длительностью около 48.11 s, `s_inGame` около 53.99 s, sound effects победы/ворот/Boss/заклинаний/оружия и UI.

## 6. Архитектура запуска и игровой цикл

### 6.1. Preloader

[SWF] `Preloader` устанавливает `NO_SCALE` и `TOP_LEFT`, подключает обработчики progress/error/enter-frame и показывает `v0.99.99.55`.

Если URL домена имеет префикс `kizi.com`, preloader:

- включает `Preloader.oopla=true`;
- вызывает `Security.allowDomain("*")`;
- устанавливает context `stormy-castle`;
- устанавливает auth token `3847409a3f71fb0a81d174caf7bb5633`;
- вызывает `OoplaAPI.connect(stage, root.loaderInfo, OoplaLogger.DEBUG)`.

У Oopla-клиента:

- API version: `0.128`;
- URL по умолчанию: `http://oopla.com/api/ooplaAPI.swf`;
- URL можно заменить параметром `apiSwfUrl` в loaderInfo;
- timeout загрузки API: 20,000 ms;
- API-классы проксируют `vault`, `gameState`, inventory, user login и coin balance.

Для обычной ветки Oopla выключен, создаётся `scrPreloader`, обновляются bar/text-проценты и затем запускается `Main.startGame`.

### 6.2. `Main`

`Main.init`:

1. устанавливает `StageScaleMode.SHOW_ALL`;
2. сохраняет статическую ссылку на stage;
3. создаёт preloader graph и `ResManager`;
4. регистрирует ресурсы аур, hit-effects, projectiles и анимаций;
5. вызывает `Playtomic::Log.View` с game ID `962243`, public key `27cd2923fe5148a7` и GUID `64a7e6d5d04840b7b616c3cbea880e`;
6. при доступном Oopla регистрирует callback на `USER_LOGGED_IN` и `COIN_BALANCE_CHANGED`;
7. создаёт `GameEngine`, подписывает stage на click и keyboard events.

Статические defaults Playtomic начинаются как `Enabled=false`, `SWFID=0`, пустой GUID, `UseSSL=false`, `PEventsEnabled=false`. Однако `Main.init` сразу вызывает `View` с ненулевыми ID, поэтому в обычном запуске библиотека может включиться и отправлять View/Play/Level events, если сеть доступна.

`Main` также содержит `ExternalInterface`-ветки:

- callback `startGame` для host page;
- callback `setPreloaderProgress` для Oopla/Kizi-страницы;
- переход на `http://www.iriysoft.ru` из UI.

### 6.3. Создание мира

`GameEngine` и связанный in-game state создают:

- `Map` и `MapType`;
- `VisualWorld` с ground/enemy/player/structure/projectile/gui слоями;
- `ChangedObj` для player и enemy;
- `MagicEffects`;
- `ActionWorld`, `Actor`, `Effect`, `ModifierEffect`;
- `AIEngine`/`AIBasic` или `AI_waves`;
- `scr::InGamePanel`;
- dictionaries/list-коллекции для enemy, structures, targets и projectiles.

В зависимости от `GameData.gemeReg` выбирается Normal, Hard, Boss или Flow branch. Затем отрисовывается castle/background, строятся дороги/мосты/ворота/шахты, загружается выбранный AI и включаются magic buttons.

[SWF] Основной update идёт с целевым `30 fps`. `Enemy.update` обновляет путь, вращение, скорость, выбор цели, recharge timers, эффекты и рендер. `MagicEffects.magicUpdate` отсчитывает Meteor/Armageddon timers. `ChangedObj.updateMoney` переносит накопленные silver/gold в общий money count и применяет research multiplier.

## 12. Магия

Пять кнопок UI в runtime-порядке: **Meteor, Teleport, Holy, Armageddon, Money**. В `objUp` definitions они названы соответственно `Magic2_meteor`, `Magic5_teleport`, `Magic3_holy`, `Magic4_armagedon`, `Magic1_money`.

| Spell | Activation | Точная логика из SWF |
|---|---:|---|
| Meteor | key `1` | `addMeteor` создаёт `mcFireBallAnim`, ставит timer `0.75 s`; затем `fireBallEffect` проверяет расстояние `distance < radius + target.radius` и применяет area damage с `fireballRadius`/`fireballDamage` |

## 14. AI и Flow waves

### 14.1. Обычный AI

`AIBasic` получает per-map preset, hard/boss parameters и upgrade order. Он умеет:

- выбирать production structures;
- строить towers/structures;
- выпускать units на random road;
- исследовать upgrades через `myOrderUp`;
- использовать enemy Meteor через `needFireball` и `FireBallTimer`;
- менять money, gate HP, mine rate и production speed через enemy `ChangedObj`.

Внутренняя catch-up логика:

- `setCheetUp` и поле `cheetTimer` существуют в AI;
- когда AI оказывается в отставании/не выполняет нужные условия, он может получить ускорение и временные строительные преимущества;
- это внутренняя rubber-band/catch-up механика, а не подтверждённый cheat-код игрока.

Волновой AI также содержит `arrAllUp` из ranged speed/range, all HP, magic defense, siege range/damage и magic speed upgrades. В зависимости от `levelDiff` он добавляет units, случайно исследует upgrade и может использовать enemy Meteor. Это удобнейшая точка для создания новых wave-профилей.

## 15. Tutorial как документ механик

`TutorScr::static_init` содержит не только подсказки, но и scripted test scenario. Подтверждённые сообщения/tutorial objectives:

- защищать свои ворота;
- уничтожить вражеские ворота для победы;
- построить Barracks и Archery Range;
- изменить game speed;
- увидеть Boss Den и дождаться Boss timer;
- в Boss mode убить Boss или разрушить enemy gates;
- открыть Meteor, выбрать spell и бросить его в выделенную область;
- строить Archer Turret и наблюдать автоматическую атаку;
- ranged units могут атаковать любую цель в range;
- улучшить дальность лучников через Blacksmith/Improved Arrows;
- ускорить создание дополнительной единицы за деньги;
- открыть Mining и повысить income через Town Hall;
- upgrade buildings, чтобы производить units быстрее;
- использовать Teleport на дороге;
- активировать Shelter, чтобы войска остановились;
- Shelter защищает от Meteor, но блокирует healing;
- дороги разделяют бои, bridge даёт ranged cross-road interaction;
- каждое здание назначено одним из ворот;
- здания можно выбирать и назначать массово;
- counter: warrior > archer, archer > wizard, wizard > warrior.

Это сильнее рекламных описаний: tutorial является частью того же SWF, который запускает игру.

### 16.4. Чем это извлекать

Практический рабочий процесс:

1. сделать копию SWF;

3. при необходимости распаковать CWS-контейнер;
4. экспортировать Sound tags в MP3, картинки/frames в PNG, векторные ресурсы в SVG/shape-формат, текст и P-code в TXT;

## 18. Аномалии и осторожные места

1. `StormyCastle0.9`, preloader `v0.99.99.55`, Softpedia `0.99.99.55` и внешние версии 0.9/1.0 отражают разные уровни version labeling.
2. SWF metadata оставляет creator/publisher `unknown`; Gamekens и IriySoft нельзя безоговорочно слить в одного автора.
3. Внутренние названия содержат много опечаток: `Cloods`, `Prists`, `Cavalery`, `Factoory`, `Repear`, `complit`.
4. UI production text не всегда совпадает с runtime production interval; для баланса читать ABC constructor, а не только label.
5. `TH_SPEED_CREATE_UP` имеет подозрительный base value `-1`; это сохранено как факт, а не исправлено.
6. `MG_GOLD_MINE` имеет первый raw cost `0`; это также оригинальное значение.
7. `infin_STRUCT` с cost `10000000` и `NOVIS_STRUCT` — служебные/тестовые definitions, не обычные buildings.
8. Boss имеет 6000 HP и обычный damage 520, но Armageddon специально отнимает у Boss только 300 вместо 100000.
9. Playtomic по умолчанию disabled, но Main вызывает View с ненулевыми credentials/ID и может включить transport.
10. Oopla активируется только для Kizi-domain branch, но код содержит default API URL и возможность переопределить его параметром.
11. Наличие `iriysoft` namespace доказывает использование этого кода/SDK, но не является самостоятельным доказательством юридического авторства.
12. Hacker comments `A/T/H/B/M/C` и unlimited spells не нашли подтверждения в keyboard handler.
13. Часть внешних screenshot/image-search результатов относится к другим играм; изображения нельзя использовать для восстановления механик этой версии.

## 19. Итог

`0.swf` содержит практически всю игру, а не только графический клиент. Его наиболее ценные для анализа слои — статические constructors с definition tables и method bodies с runtime behavior. Самые безопасные модификации — data-table edits, карты, звуки/ресурсы, UI и tutorial. Более глубокие правки возможны, но требуют AVM2-aware decompiler/compiler и тестирования в Flash/Ruffle-совместимом окружении.

Из файла можно отдельно получить:

- музыку и все звуки;
- PNG/SVG/кадры спрайтов и MovieClip-анимаций;
- background, castles, minimaps, UI и effects;
- ASCII-карты;
- таблицы зданий, юнитов, projectile и AI;
- строки и tutorial;
- реконструированный AS3/AVM2-код.

В текущем состоянии исследования исходный `0.swf` сохранён без изменений; отчёт является отдельным deliverable.
